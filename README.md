# Behavioral Tool-Selection Corpus for Cybersecurity Agents

Dataset and code for the paper on building an explainable behavioral tool-selection
corpus for cybersecurity AI agents, with smart-tool training and Neural Input
Optimization (NIO) explainability.

Everything here runs from one CSV. No SSH, no live LLM, and no network are
required to reproduce the results.

## Files

| File | What it is |
|---|---|
| `cyber_logs.csv` | The dataset: 640 rows, one per query. Columns: `prompt`, `tool_predicted` (the local LLM's tool choice), `tool_ground_truth` (the correct tool), `agent_role`, `difficulty` (easy/hard), `category`. |
| `01_data_collection.ipynb` | How the `(prompt, tool)` pairs are collected (logging wrapper), the label distribution, and the LLM baseline including per-category accuracy. |
| `02_svm_training.ipynb` | TF-IDF + SVM (and LogReg/MLP/RandomForest). 5-fold cross-validation and the confusion matrix. |
| `03_llama_vs_smarttool.ipynb` | Single comparison: local LLM (Llama 3.2) tool choice vs the trained smart tool, on 10 held-out tasks. Runs from the CSV; an optional cell re-runs the LLM live if Ollama is installed. |
| `NIOexplainability.ipynb` | Neural Input Optimization: trains an agreement/disagreement model and finds the terms that drive the LLM's tool-selection errors. |
| `confusion_matrix.png` | Generated by `02_svm_training.ipynb`. |

## Run

```
pip install -r requirements.txt
jupyter notebook       # open any notebook, then Kernel > Restart & Run All
```

Keep `cyber_logs.csv` in the same folder as the notebooks.

## Expected results

- LLM baseline (Llama 3.2 3B): 79.4% overall, 73.5% on hard queries.
- SVM (5-fold CV): about 98% overall, about 94% on hard queries.
- 10-task comparison: LLM 9/10, smart tool 10/10.
- NIO: the disagreement model reaches ~93.75% and flags port-scanning terms;
  about 54% of the LLM's errors are NmapScan vs PortScan confusion.
